2. วัตถุประสงค์ ขอบเขต และคำถามวิจัย

2.1 เป้าหมายตาม implementation

  • สร้าง pipeline ที่โหลด dataset ภาษาไทยจาก Hugging Face, คัดข้อมูล, split แบบทำซ้ำได้ และเก็บ provenance/hash
  • ทดลอง fine-tune mT5-small ด้วย input-output text pairs ที่เตรียมไว้
  • ประเมิน mT5 บน held-out test split ด้วย lexical metrics และบันทึก predictions
  • มี CLI สำหรับทดลองเรียบเรียงด้วย Thai instruction model และ guard ที่ลดความเสี่ยงบางแบบ

2.2 ขอบเขตที่ยังไม่ใช่ข้ออ้างของงาน

  • ไม่ใช่ระบบ paraphrase ที่พิสูจน์ semantic equivalence แล้ว
  • ไม่ใช่ระบบ style transfer ที่ train ด้วยระดับ formal/semiformal/casual labels
  • CLI ไม่ได้ใช้ weights mT5 ที่ train ในโครงงาน; ใช้ Typhoon2 checkpoint แยก
  • ยังไม่มี blind human evaluation, significance test, หรือ benchmark เทียบ baseline หลายตัว

2.3 ถ้ากรรมการถาม “สมมติฐานคืออะไร”

ตอบอย่างระมัดระวังว่า “สมมติฐานเชิงวิศวกรรมคือ สามารถสร้าง pipeline ตรวจสอบย้อนกลับและ fine-tune multilingual seq2seq model กับ Thai synthetic instruction pairs ได้ ส่วนสมมติฐานว่าคุณภาพ paraphrase ดีขึ้นยังต้องทดสอบด้วย dataset ที่ตรงงานและ human evaluation; หลักฐานปัจจุบันยังไม่พอรับรอง”

4. Algorithm: split, training, evaluation

4.1 Deterministic split

records = accepted_pairs.copy()
random.Random(42).shuffle(records)
n_test = round(len(records) * 0.10)
n_val  = round(len(records) * 0.10)
test       = records[0 : n_test]
validation = records[n_test : n_test + n_val]
train      = records[n_test + n_val :]

Python round ใช้ round-half-to-even: 4,865 × 0.10 = 486.5 จึง round เป็น 486. ได้ test=486, validation=486 และ train=3,893. Source ซ้ำ exact ถูกตัดก่อน split; near-duplicate เชิงความหมายอาจยังมีได้

4.2 Input/target format สำหรับ mT5

input text  = "instruction: " + instruction + "\\ncontext: " + source_text
target text = target_text
source token cap = 512
target token cap = 384

Tokenizer แปลง text เป็น token IDs. mT5 encoder อ่าน instruction+context และ decoder ทำนาย target แบบ autoregressive. Labels มาจาก target token IDs; padding/label handling ใช้ DataCollatorForSeq2Seq

4.3 Loss และ optimizer

Seq2seq supervised fine-tuning ใช้ token-level negative log-likelihood/cross-entropy: L = -Σ log pθ(yₜ | y<ₜ, x) เฉลี่ยบน target tokens ที่ไม่ใช่ padding. Gradient จาก loss ย้อนผ่าน decoder/encoder แล้วอัปเดต weights. Optimizer ใน serialized TrainingArguments ของ run นี้คือ adamw_torch_fused; weight decay 0.01. LR scheduler เป็น linear, warmup_steps=0

ถ้าถามว่าทำไมบอก AdamW fused: source code ไม่ได้ส่ง optim=... เข้า Seq2SeqTrainingArguments เอง; ค่านี้อ่านจาก artifacts/checkpoints/checkpoint-487/training_args.bin ของ run ที่บันทึก จึงควรพูดว่า “ค่าที่ run นี้ serialize ไว้” ไม่ใช่ค่าที่ hard-code ใน train.py

Training report ไม่บันทึกชื่อ device/GPU. 6. Evaluation: metrics กับการตีความ

6.1 Algorithm ของ evaluate.py

  1. อ่าน 486 แถวจาก data/test.jsonl; test ไม่ถูกส่งเข้า train.py
  2. สร้าง input ด้วย instruction/context; padding/truncate สูงสุด 512 tokens
  3. batch size 4, max_new_tokens 256, beam size 4, do_sample=False
  4. decode predictions แล้วจับคู่กับ target_text reference
  5. คำนวณ corpus chrF กับ SacreBLEU และ mean ROUGE-L F1
  6. บันทึก metrics ใน evaluation_report.json และทุกคู่ source/reference/prediction ใน predictions.jsonl

7. CLI model และ guard

7.1 ทำไมมีสองโมเดล

mT5 เป็น encoder-decoder ที่ fine-tune จาก weak summarization pairs; การลอง inference แสดงการเลียน instruction, special tokens และเวลาเปลี่ยน จึงเก็บไว้เป็น baseline ที่มี training/eval evidence. Typhoon2 Llama3.2 3B เป็น instruction model ภาษาไทย pretrained จากผู้พัฒนาโมเดล; smoke tests บนประโยคเวลา/จำนวนงานดีขึ้น จึงเป็นโมเดลที่ app.py โหลดตอน CLI. ไม่ได้ fine-tune Typhoon ด้วย project dataset

7.2 Inference decoding

  • Model ID: typhoon-ai/llama3.2-typhoon2-3b-instruct; model card: Thai/English, 3B, Llama 3.2 Community License
  • ใช้ tokenizer chat template เพื่อจัด system/user messages ให้เข้ารูปแบบที่โมเดลคาดหวัง
  • system prompt สั่งให้รักษาข้อมูลเดิม, ห้ามเพิ่มเวลา/ตัวเลข/ข้อเท็จจริง, ตอบเฉพาะข้อความ
  • โหมดส่งชื่อ rewrite/formal/semiformal/concise; generation ใช้ greedy/deterministic setting (do_sample=False), repetition penalty 1.08, no_repeat_ngram_size 4, max_new_tokens default 128
  • ตัด prompt tokens ก่อน decode, skip special tokens, ใช้ paragraph แรกเพื่อทิ้งหมายเหตุส่วนท้าย

7.3 Guard pseudo-code

candidate = decode(generated_new_tokens).strip().first_paragraph
if blank or contains_sentinel_or_prompt(candidate): reject
if len(candidate) > max(2 * len(source), len(source) + 120): reject
normalize Thai/Arabic digits, commas, and trailing .00
if ordered_numbers(source) != ordered_numbers(candidate): reject
if source contains "เที่ยง" but not "เที่ยงคืน": expected source noon as 12
if protected_terms(source) != protected_terms(candidate): reject
if rejected: print original source + reason
else: print candidate

คำสำคัญที่ตรวจมี พรุ่งนี้/วันนี้/เมื่อวาน/มะรืน/เที่ยงคืน/บาท/เปอร์เซ็นต์. Guard นี้เป็น heuristic และยังตรวจไม่ครอบคลุมเลขที่เขียนเป็นคำไทย, ชื่อเฉพาะ, หน่วยทุกชนิด, ความหมายเชิงปฏิเสธ หรือข้อเท็จจริงทั่วไป

8. คำถามกรรมการพร้อมแนวตอบ

Q1: โครงงานนี้ทำอะไร และปัญหาคืออะไร?

A: ทำ pipeline ทดลองเรียบเรียงข้อความภาษาไทย โดยสนใจ fluency และระดับภาษา แต่จากการตรวจข้อมูลพบว่า dataset ที่กำหนดเป็น instruction/summarization dataset ไม่ใช่ paraphrase corpus จึงวางขอบเขตเป็น baseline + prototype และรายงานข้อจำกัด ไม่อ้างความสำเร็จเกินผล

Q2: Algorithm ที่ใช้ train คืออะไร?

A: Supervised seq2seq fine-tuning. ประกอบ instruction+context เป็น input, output เป็น target, ใช้ token-level cross-entropy, backpropagation และ AdamW fused; scheduler linear. TrainingArguments จาก run จริงบันทึก batch 1, accumulation 8, lr 2e-5, weight decay .01, 1 epoch, seed 42

Q3: ใช้โมเดลอะไร? mT5 กับ Typhoon ต่างกันอย่างไร?

A: mT5-small เป็น encoder-decoder baseline ที่ fine-tune ด้วย dataset ในโครงงานและเป็นตัวสร้าง evaluation report. Typhoon2 Llama3.2 3B Instruct เป็น pretrained Thai instruction model ที่ CLI โหลดเพื่อทดลองใช้งาน; ไม่ได้ fine-tune ด้วย dataset นี้ จึงห้ามนำผล mT5 ไปอ้างเป็นผล Typhoon

Q4: mT5 ทำงานอย่างไร?

A: Encoder อ่าน source/context และสร้าง hidden representations. Decoder สร้าง target ทีละ token โดยมอง token ก่อนหน้าและเข้ารหัส source. ระหว่าง train ใช้ teacher forcing/labels เพื่อคำนวณ cross-entropy; ระหว่าง inference ใช้ generation

Q5: ทำไมเลือก mT5-small?

A: เป็น multilingual text-to-text pretrained model ที่รองรับ Thai และมีขนาดเล็กกว่ารุ่นใหญ่ เหมาะกับ baseline บนทรัพยากรจำกัด แต่ multilingual pretraining ไม่รับรอง downstream paraphrase quality; ต้อง fine-tune กับ task data ตรงโจทย์

Q6: Dataset มาจากไหน ใครสร้าง?

A: Hugging Face dataset โดย AIResearch/VISTEC-depa ชื่อ WangchanX Seed-Free Synthetic Instruct Thai 120k. Dataset card อธิบาย seed-free synthetic framework สร้าง Thai instruction tasks จาก topic/context sources; ระบุ generator Qwen2-72B-Instruct และ scorer Llama 3 70B Instruct. ใช้ 118,898 rows ตาม manifest

Q7: ทำไมบอกว่า dataset ไม่ใช่ paraphrase ทั้งที่มี source/output?

A: มี source/output จริง แต่ label type เป็น summarization. Summary อาจตัดรายละเอียดหรือเติมข้อมูล จึงไม่รับประกัน equivalence. การมีสองข้อความไม่ได้ทำให้เป็น paraphrase pair โดยอัตโนมัติ

Q8: ทำไมคัดเพียง 4,865 จากเกือบ 119k?

A: เลือก summarization (22,848 ก่อนกรอง), rating≥7, source/target ไม่ว่าง, target/source length 0.65–1.25, และตัด source ซ้ำ; เงื่อนไขหลายชั้นทำให้เหลือ 4,865. เกณฑ์ ratio เป็น heuristic ไม่ใช่หลักฐานความหมายตรง

Q9: ทำไม train/validation/test เป็น 80/10/10?

A: train ใช้อัปเดต weights; validation ใช้ดู eval loss/เลือก checkpoint; test เก็บไว้ประเมินหลังฝึกเพื่อลดการปรับโมเดลตาม test. ใช้ seed 42 หลัง dedup เพื่อทำซ้ำได้

Q10: ป้องกัน data leakage อย่างไร?

A: ตัด exact duplicate source จากชุด accepted ทั้งหมดก่อน shuffle/split แล้วจึงแยก splits. Hashes ของ files ถูกบันทึกใน manifest/training report. อย่างไรก็ดี pipeline ไม่ได้ตรวจ near-duplicate เชิงความหมายหรือเอกสารต้นทางเดียวกันแบบ semantic grouping

Q11: ทำไม epochs แค่หนึ่ง?

A: run ที่บันทึกตั้ง 1 epoch และมี 487 optimizer steps; เป็น baseline ภายใต้ทรัพยากรที่มี ไม่ใช่ข้อพิสูจน์ว่าเป็นจำนวน epoch ที่ดีที่สุด. การเลือก epoch ต้องทำ validation comparison/learning curves โดยไม่แตะ test

Q12: optimizer AdamW คืออะไร? ทำไม fused?

A: AdamW ใช้ first/second moments ของ gradient เพื่อปรับ step size พร้อม decoupled weight decay; fused เป็น implementation ที่รวม operations เพื่อลด overhead. ค่า adamw_torch_fused อ่านจาก training_args.bin ของ run นี้; source code ไม่ได้กำหนด explicit optimizer จึงขึ้นกับ Transformers/PyTorch version

Q13: gradient accumulation 8 หมายถึงอะไร?

A: คำนวณ gradient จาก micro-batch ขนาด 1 แปดรอบก่อน optimizer update, ทำให้ effective batch ประมาณ 8 เมื่อใช้ process เดียว ช่วยลด memory ต่อ step แต่ไม่ได้เท่ากับ batch 8 ทุกด้าน เช่น BatchNorm (ซึ่ง architecture นี้ไม่ได้พึ่งเป็นหลัก) และ throughput

Q14: learning rate scheduler ทำอะไร?

A: run นี้ใช้ linear schedule ไม่มี warmup โดยเริ่มใกล้ 2e-5 และลดลงเป็นเส้นตรงไปใกล้ศูนย์ตาม total steps. ใช้ทำให้ updates เล็กลงช่วงท้าย; ดูค่าจริงราย step ได้ใน trainer_state log_history

Q15: eval_loss ต่ำกว่า train_loss ทำไม?

A: report train_loss 7.60 เป็นค่า train metrics ที่ Trainer aggregate ระหว่าง optimization; validation eval_loss 2.1857 วัดหลัง epoch ในโหมด evaluation โดยไม่มี dropout และวิธี aggregate อาจต่างกัน. ความต่างนี้ควรตรวจ semantics ของ Trainer/version และ token masking ก่อนอธิบายว่า generalize ดี; ห้ามสรุปจากตัวเลขอย่างเดียว

Q16: chrF 23.47 กับ ROUGE-L 0.062 บอกอะไร?

A: เป็น lexical-overlap metrics เทียบ mT5 predictions กับ synthetic summarization references บน 486 tests. chrF วัด character n-gram overlap, ROUGE-L อิง longest common subsequence. ROUGE-L ที่ต่ำสะท้อน overlap ต่ำใน setup; ทั้งคู่ไม่วัดความหมาย/ข้อเท็จจริง/style และไม่ใช่ Typhoon score

Q17: ทำไมไม่ใช้ BLEU หรือ BERTScore?

A: implementation ปัจจุบันเลือก chrF กับ ROUGE-L; ไม่ควรกล่าวว่า metrics เหล่านี้เพียงพอ. งานต่อควรเพิ่ม human evaluation และ semantic/factuality checks; BLEU/BERTScore ก็มี blind spots จึงไม่ใช้ตัวใดแทนการประเมินความหมายทั้งหมด

Q18: ทำไม CLI ใช้ Typhoon2?

A: mT5 fine-tuned baseline ทดลองกับ prompt paraphrase แล้ววนซ้ำ/เปลี่ยนเวลา เพราะ training targets เป็น summary. เลือก Thai instruct model สำหรับ prototype หลัง smoke testing เพื่อให้ทำตามคำสั่งได้ดีกว่า; เป็นการเปลี่ยน inference model ไม่ใช่ผล fine-tune จาก dataset โครงงาน

Q19: Typhoon2 ฝึกด้วย data นี้หรือไม่?

A: ไม่. CLI โหลด pretrained Typhoon2 Llama3.2 3B Instruct จาก Hugging Face; project dataset train ไปที่ mT5 เท่านั้น. ต้องรายงาน model roles แยกกันชัด

Q20: Guard รับรองว่าความหมายไม่เปลี่ยนไหม?

A: ไม่. Guard ปฏิเสธ marker/prompt leaks, output ยาวผิดปกติ, ตัวเลขไม่ตรง และ protected terms บางคำเท่านั้น; คืน source เมื่อเจอความเสี่ยง. ยังตรวจ semantic equivalence, names, negation, units ที่ไม่อยู่ใน list และเลขเขียนเป็นคำไม่ได้ครบ

Q21: ทำไมผลตัวอย่างเปลี่ยน “เที่ยง” เป็น “12.00 น.” แล้วยอมรับ?

A: Validator มีกฎเฉพาะ: เมื่อ source มี “เที่ยง” แต่ไม่ใช่ “เที่ยงคืน” เพิ่มค่า 12 เข้า expected numeric values; จากนั้น normalize 10/10.00 และ 12/12.00. นี่คือ equivalence heuristic เฉพาะรูปแบบ ไม่ได้เข้าใจเวลาโดยทั่วไป

Q22: ถ้าตัวเลขใน output ถูกต้องแต่เนื้อหาอื่นเปลี่ยน guard จะรู้ไหม?

A: อาจไม่รู้. ตัวเลขตรงไม่ได้แปลว่าข้อเท็จจริงทั้งหมดตรง; ต้องให้คนตรวจหรือเพิ่ม evaluation/constraint methods. จึงควรเรียก guard ว่าตัวกรองความเสี่ยงเบื้องต้น

Q23: ทำไมไม่มี dataset paraphrase เพิ่ม?

A: ในการตรวจครั้งนี้ไม่พบ corpus ไทยที่สามารถยืนยัน schema/license/คุณภาพและนำมาใช้ได้ทันทีโดยไม่ตรวจเพิ่ม. ไม่ควรสร้างคู่เทียมจาก QA/brainstorming เพราะ input-output ไม่ใช่ paraphrases. ขั้นต่อไปคือเลือก licensed paired corpus หรือสร้าง human-annotated pairs และบันทึก provenance

Q24: โปรเจกต์ “ใช้งานได้จริง” แล้วหรือยัง?

A: CLI รันได้และมี fallback guard แต่ยังเป็น research prototype; มี smoke tests สองกรณีเท่านั้น ไม่มี human evaluation หรือ task-aligned benchmark จึงยังไม่อ้าง production-ready

Q25: ถ้าจะทำต่อให้เป็นงานวิจัยที่ตอบโจทย์ จะทำอะไร?

A: กำหนด paraphrase/style taxonomy, เก็บหรือเลือก paired Thai data ที่ license ชัด, annotation guideline และ inter-annotator check; split กัน leakage; เทียบ pretrained baseline กับ fine-tuned models; ทำ human blind evaluation, error analysis, factual preservation metrics; pin model revisions และเก็บ device/environment/config
