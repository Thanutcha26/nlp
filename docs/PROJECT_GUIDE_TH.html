4. ชุดข้อมูลและอัลกอริทึมการเตรียม

4.1 ที่มาและ schema

แหล่งข้อมูลคือ airesearch/wangchanx-seed-free-synthetic-instruct-thai-120k ซึ่ง manifest ระบุ 118,898 rows ใน train split, fingerprint 24a35b6a961cfde3, license MIT ตาม dataset card และ citation งาน ACL SRW 2024

ตัวอย่างใน JSONL มี keys: source_text, target_text, instruction, rating, source_index. ใน source dataset ใช้ context เป็นข้อความต้นทางและ output เป็นคำตอบเป้าหมาย

ชนิดข้อมูลใน sourceจำนวนแถว
conversation24,865
multiple_choice23,975
brainstorming23,844
question_answering23,366
summarization22,848

4.2 ตัวกรอง

  1. ถ้า type != summarization ให้ reject
  2. ตัด whitespace ที่หัว/ท้าย source และ target; ค่าว่างอย่างใดอย่างหนึ่งให้ reject
  3. แปลง rating เป็น float และต้อง rating >= 7.0
  4. คำนวณ r = len(target) / len(source) ด้วยจำนวนตัวอักษร Unicode ของ Python; รับเฉพาะ 0.65 <= r <= 1.25
  5. สร้าง SHA-256 จาก source ที่ trim แล้ว; source hash ที่เคยพบแล้วจะ reject
  6. เก็บ source/target/instruction/rating/index ไว้
for each source row:
  if type != summarization: reject
  source = trim(context); target = trim(output)
  if source or target is empty: reject
  if rating < 7: reject
  ratio = character_count(target) / character_count(source)
  if ratio outside [0.65, 1.25]: reject
  if sha256(source) already seen: reject
  accept(source, target, instruction, rating, source_index)

5. อัลกอริทึมการฝึก mT5

5.1 การแปลง input/target

สำหรับแต่ละแถว train/validation สคริปต์ประกอบ input เป็น instruction: {instruction}\ncontext: {source_text} แล้ว tokenize โดยตัดที่ 512 tokens. Target tokenize แยกด้วย text_target และตัดที่ 384 tokens. Data collator ทำ padding ให้ batch และตั้ง labels สำหรับ seq2seq loss

5.2 การเรียนรู้

mT5 เป็น encoder-decoder seq2seq. Encoder อ่าน token ของ instruction + source; decoder เรียนรู้ทำนาย target token ทีละตำแหน่งโดยใช้ teacher forcing. วัตถุประสงค์เป็น token cross-entropy: ลดความคลาดเคลื่อนระหว่าง token เป้าหมายและการกระจายความน่าจะเป็นที่โมเดลทำนาย

input_ids = tokenize("instruction: ...\\ncontext: " + source)
labels    = tokenize(target)
for batch in train:
  logits = mT5(input_ids, labels=labels)
  loss = token_cross_entropy(logits, labels)
  backpropagate(loss)
  optimizer.step() when gradient accumulation reaches 8 micro-batches
  evaluate validation loss at each epoch end
keep checkpoint with lowest eval_loss

6. การประเมินผลและหลักฐาน

6.1 วิธีของ evaluate.py

  1. อ่าน test split ทั้งหมด (ค่า default --max-samples 0 หมายถึงทั้งหมด)
  2. สร้าง prompt จาก instruction + source; tokenize padding/truncation ที่ 512 tokens
  3. แบ่ง batch ค่าเริ่มต้น 4; generate ได้ไม่เกิน 256 tokens, beam search 4, deterministic (do_sample=False)
  4. คำนวณ corpus chrF เทียบ reference และค่าเฉลี่ย ROUGE-L F1
  5. เขียนทุก prediction ไป artifacts/predictions.jsonl และ report ไป artifacts/evaluation_report.json

6.3 Human evaluation ที่ยังต้องทำ

แนวทางก่อนนำเสนอ: สุ่ม test examples, แสดง source/reference/model output แบบไม่ชี้นำ, ให้ผู้ประเมินอย่างน้อยสองคนให้คะแนน fluency, meaning preservation และ style appropriateness ระดับ 1–5 พร้อมทำเครื่องหมาย factual drift (ใช่/ไม่ใช่), แล้วรายงานคะแนนแยก/ความเห็นไม่ตรงกัน ปัจจุบันยังไม่มีไฟล์ผล human evaluation ใน repository

7. CLI, Typhoon2 และ output guard

7.1 การสร้าง prompt และผล

app.py ใช้ AutoTokenizer/AutoModelForCausalLM ของ Typhoon2, ประกอบ system/user messages, แล้ว serialize ด้วย chat template ของ tokenizer เพื่อได้ input token IDs. Model generate ใช้ do_sample=False, repetition_penalty=1.08, no_repeat_ngram_size=4 และ max_new_tokens ที่ผู้ใช้กำหนด (default 128). เนื่องจาก do_sample=False ผลจะ deterministic สำหรับ weights/prompt/config เดิม

หลัง generate จะตัด token IDs ของ prompt ออกจากลำดับรวมก่อน decode, ลบ special tokens, trim whitespace และเก็บเฉพาะย่อหน้าแรกเพื่อตัดหมายเหตุแถมที่โมเดลอาจสร้าง

7.2 Guard เชิง heuristic

ตรวจอะไรวิธีเมื่อพบปัญหา
คำตอบว่างstrip แล้วตรวจ emptyคืนเหตุผล reject
prompt/sentinel รั่วหา <extra_id_, instruction:, context:, โปรดเรียบเรียงไม่แสดง output; ใช้ source
ความยาวผิดปกติreject เมื่อยาวกว่า max(2×source, source+120)fallback เป็น source
ตัวเลขดึงเลขอารบิก/ไทย, normalize เลขไทย, comma, ทศนิยม .00; หาก source มี “เที่ยง” (ไม่ใช่เที่ยงคืน) เพิ่มค่า 12 ที่คาดหมายต้องตรงลำดับตัวเลข ไม่เช่นนั้น fallback
คำสำคัญที่กำหนดเปรียบเทียบ subset ของ วันนี้/พรุ่งนี้/เมื่อวาน/มะรืน/เที่ยงคืน/บาท/เปอร์เซ็นต์หากเพิ่ม/หายไป fallback

Guard ไม่ได้ตรวจความหมายทั่วไปหรือข้อเท็จจริงทุกชนิด เช่น ชื่อคน หน่วยอื่น ข้อปฏิเสธ ความสัมพันธ์เชิงเหตุผล และเลขที่เขียนเป็นคำ จึงเป็นการลดความเสี่ยงบางกลุ่ม ไม่ใช่ formal guarantee

7.3 โหมด

CLI modeคำสั่งที่ส่งให้โมเดลหมายเหตุ
rewriteเรียบเรียงใหม่default
formalเรียบเรียงเป็นภาษาทางการไม่มี supervised formality labels ใน training data
semiformalเรียบเรียงเป็นภาษากึ่งทางการผลขึ้นกับ pretrained model/prompt
conciseเรียบเรียงให้กระชับความกระชับอาจตัดรายละเอียด จึงควรตรวจ

prepare_data.py จะดาวน์โหลด source dataset ถ้ายังไม่มี cache. train.py ใช้ CPU ได้แต่ช้า; evaluate.py ใช้ test ครบ 486 ตัวอย่างเป็นค่าเริ่มต้น. อย่ารัน train ซ้ำถ้าต้องการเพียงทดลอง CLI

8.3 ใช้งาน CLI

python app.py
python app.py --mode formal --text "พรุ่งนี้ระบบจะปิดปรับปรุงตั้งแต่ 10 โมงเช้าถึงเที่ยง"
python app.py --mode concise --text "บริษัทจะจัดส่งสินค้าภายใน 3 วันทำการหลังยืนยันการชำระเงิน"

ครั้งแรกจะโหลด Typhoon2 ประมาณ 6.5 GB ไปยัง Hugging Face cache; ข้อความ generation ใช้ CPU ได้แต่ช้ากว่า GPU. ถ้า guard ปฏิเสธผล โปรแกรมจะแสดงเหตุผลและข้อความต้นฉบับแทน

8.4 ไฟล์รายงาน

เตรียมข้อมูล → data/manifest.json; ฝึก mT5 → artifacts/training_report.json; ประเมิน mT5 → artifacts/evaluation_report.json และ artifacts/predictions.jsonl. การเรียก CLI ไม่เขียน report โดยอัตโนมัติ และไม่มี telemetry ของผลผู้ใช้

9. ข้อจำกัด ความเสี่ยง และงานต่อ

  1. Task mismatch: source data เป็น summarization; target อาจตัด/เพิ่มรายละเอียด จึงไม่ใช่ gold paraphrase
  2. mT5 baseline มีพฤติกรรมผิด: เคยสร้าง output ซ้ำและเปลี่ยนเวลา; ไม่ใช้เป็นโมเดล CLI ปัจจุบัน
  3. Typhoon ไม่ได้ fine-tune ด้วย project data: ทำให้ CLI ทดลองได้ดีขึ้น แต่ผลนี้ไม่ใช่ผลการฝึกจาก WangchanX dataset
  4. ไม่มี controlled-style labels: formal/semiformal/concise เป็น prompt modes ไม่ใช่ความสามารถที่วัดรับรอง
  5. Guard มีขอบเขตจำกัด: heuristics ตรวจเฉพาะ marker, length, ตัวเลข และคำสำคัญบางคำ; ไม่รับรอง semantic equivalence
  6. ผลประเมินคนละโมเดล: metrics ใน report มาจาก mT5 บน summarization targets; ห้ามนำไปอ้างว่า Typhoon CLI ได้คะแนนดังกล่าว
  7. ทรัพยากร: Typhoon2 ใช้ RAM/เวลาเพิ่ม; เครื่องที่ไม่มี CUDA จะทำงานบน CPU

งานต่อที่มีหลักฐานรองรับ

  • หา/จัดทำ Thai paraphrase pairs ที่มี source, target, style labels และ license ตรวจสอบได้; อย่าแปลง QA/brainstorming เป็นคู่ paraphrase โดยไม่มี annotation
  • ทำ train/validation/test สำหรับ task ใหม่โดย split ตาม source/document group ป้องกัน leakage
  • สร้าง regression set ที่มีตัวเลข เวลา วันที่ หน่วย ชื่อ และ negation; ตรวจ exact preservation และ human review
  • ประเมิน Typhoon CLI แยกจาก mT5 ด้วย sample set เดียวกันและบันทึก model ID/revision, prompt, decoding params
  • รายงาน human ratings และ error analysis ก่อนกล่าวอ้างว่าใช้งานเชื่อถือได้
